# 修正した7問の正しい解答をモデルから生成させる計画

**不採用：ユーザーは7問の丸暗記と、人が問題・分野を選んで教え込む方法を明確に希望していない。以下は以前の提案の記録であり、実行しない。** 最新は[人手で問題を選ばない自動学習の計画](20261015_automatic_reasoning_training_plan.md)。

2026年10月15日 JST。ユーザーの訂正を受けた目的の再整理。計画のみで、教材作成・学習・提出は未実行。

## 目的と前案の訂正

終了トークンの重み付けは、7問の計算・符号・式変形の誤りを直接教え直す方法ではなかった。前案では出力の反復という副次的な問題を主目的にしてしまった。今回は「修正した7問について正しい解答を生成させる」を主目的とし、停止挙動は品質確認の一項目に戻す。

同じ7問の再現と、未見の類題への一般化は分けて測る。前者を直接実現する方法は、元の問題文を入力、修正済み解答を教師出力とするSFTである。後者には、誤った演算に対応した独立した教材と評価が必要になる。

## 同じ7問の解答を覚えさせる実験

1. 元の7問の完全な入力を回収し、実際の推論テンプレートで整形する。回答から問題文を推測して代用しない。指定のdocxは使用しない。
2. 対応するfix7の修正答案を教師出力にする。文字列の完全再現が目的なら本文を変更しない。数学的な正解が目的なら、最終答えだけでなく途中式も独立に検算した教師解答を用意し、元fix7とは別の教材版として保存する。
3. run03のコピーからLoRAを継続し、問題文をmaskして解答本文と終了位置に通常のCEをかける。教師の正しいトークン列を直接学ぶことが本実験の変更点。run06のような「記号が多い別の2,400問」の復習ではない。
4. 最初は7問のみの小さな適合実験を行う。既存rank8/alpha16、学習率1e-5を初期候補に、全7問を1更新の実効batchとし、10更新ごとに自由生成、上限100更新で確認する。これらは試験設定であり、再現を保証する値ではない。lossだけを見て成功としない。
5. 正解文を推論入力に渡さず、元の問題文だけからgreedyで再生成する。7問の数学的正答率、教師文字列との完全一致、反復・打切りを別々に記録する。教師強制中の予測精度と自由生成での成功を混同しない。
6. 保存・再ロードしたadapterからも生成できることを確認する。元run03を保存し、独立devで他の能力への影響を確認する。7問への適合後に一般教材を混ぜる実験を行う場合も、7問の露出回数を記録する。

この実験は小規模な記憶・適合の確認である。7問に対して正しいトークンの確率を直接上げるため、前案より目的に対応している。ただし少数例のSFTでも全文完全一致や全問正答は保証されず、未見問題を解く能力の向上を示すものではない。

学習後に新しく生成した答案はモデルの直接出力と呼べるが、**その7問は学習済み問題になる**。「未編集のモデル出力か」と「未見問題への性能を測ったか」は別の事項である。結果には7問を学習に使ったことを明記し、その7問の改善を独立した評価性能として扱わない。大会での使用可否は本計画では判定していない。

## 同じ誤りを別の問題でも直す場合

対象となる演算を教材設計の単位にする。

| 既知の誤り | 教える手順・独立教材の対象 |
| --- | --- |
| 符号付き整数の積 | 符号を先に決定し、整数積を分解して検算 |
| 積の4乗根 | 素因数の指数を4で割って外に出す。実数での符号・定義域も確認 |
| 標本分散 | 平均、各偏差の平方、総和、n−1の分母を別々に計算 |
| 合成関数の微分・くくり出し | 連鎖律を適用し、因数分解前後の式の同値性を検算 |
| 三角関数の積分の符号 | 置換の係数を追跡し、得られた原始関数を微分して確認 |
| 行列式 | 余因子の符号と小行列、または行基本変形の係数を保持 |
| 有理数の減算 | 分母を揃えて整数演算し、符号と約分を検算 |

最初の候補は各分野100件程度の検算済み教材＋一般数学教材を同数程度混ぜるSFT。件数や混合比は独自の初期案で、論文で保証された最適値ではない。教材として使用できる範囲を満たす既存例をまず調べ、不足分の合成教材は採用可能な範囲で作る。修正した7問を直接学習する実験とは分離して保存する。

単に数値だけ変えた近接例への適合と一般化を混同しないよう、評価には異なる数値・式の構造・文章表現を含め、生成元テンプレートや問題familyの重複も検査する。SymPy等による最終式の一致だけでは解説の全手順の正しさを保証しないため、途中式の等価性・定義域・標本/母分散の条件も検査する。

[Scaling Relationship on Learning Mathematical Reasoning with Large Language Models](https://arxiv.org/abs/2308.01825)のRFTは、生成した推論経路から正しいものを選んで再学習する方法を調べている。今回の類題でモデルが正解経路を生成できるなら、検証済み経路を教師にする候補になる。初期正答がほぼ得られない分野では、まず正しい教師解説を与えるSFTを優先する。

[Training Verifiers to Solve Math Word Problems](https://arxiv.org/abs/2110.14168)は生成解答の検証を研究している。ただし、最終数値が合うだけでは途中推論が正しいとは限らない。今回は出力候補を提出時に選別する方式ではなく、学習教材の検査に検証を利用し、評価は単発生成で行う。

## RTX 6000 Adaと2〜3時間枠

48GB GPUは同時処理と学習・評価の高速化に使う。7問のみの実験は特に環境準備・モデル読み込みの比重が大きいため、前案の2,400件×2枝の時間配分を流用しない。準備・入力回収と検算に最大45分、短い適合実験と7問の自由生成確認に最大45分、独立devと保存に残り時間を予約し、合計180分を上限にする。実際の速度を測り、未完了の場合は未完了として保存する。

一般化用教材の生成・検算までこの枠に必ず収まるとは仮定しない。同じ7問の適合実験か、未見類題の改善実験かを実行manifestで明記する。両者の成績を合算しない。学習・推論の環境互換性や高速化設定は[前案のGPU節](20261015_termination_aware_training_plan.md)を再利用する。
